RECEIVER CUTAWAY

Verification happens before interpretation.

raw bytes
01

Authenticate

Compute HMAC-SHA256 over timestamp.body. Reject missing, stale, or mismatched signatures.

Nothing stored on rejection
02

Validate

Parse a small envelope only after the request is trusted: UUID, event type, created time, and data.

Malformed envelope → 422
03

Claim atomically

Hash the raw body. A BEGIN IMMEDIATE transaction decides new, duplicate, or collision.

No check-then-insert race
04

Leave evidence

Append attempt metadata and the digest. The event’s data object never reaches disk.

Useful without becoming a payload archive

CASE CONCLUSION

The transport delivered the same event twice, which is normal at-least-once behavior. The reference receiver claimed it once. If production fulfilled twice, the next investigation is where production places its side effect relative to its idempotency claim—not whether the provider retried.

HONEST BOUNDARIES

A lab, not a webhook platform.

IT PROVES
  • Raw-body HMAC verification
  • Timestamp tolerance
  • Atomic event claiming
  • Duplicate vs collision evidence
  • Digest-only retention
IT DOES NOT CLAIM
  • Exactly-once HTTP delivery
  • Provider-specific compatibility
  • Distributed production storage
  • A retry queue or dead-letter service
  • Universal event ordering
Production handoff

Claim durably, enqueue work, return quickly. Add authenticated operational views, managed storage, metrics, tracing, and a domain-specific ordering policy.
