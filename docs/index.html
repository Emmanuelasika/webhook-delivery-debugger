Receiver pipeline

The order is the safety model

The receiver does not parse first and decide later. Each gate rules out a different failure mode.

  1. 01
    Read exact bytes

    Preserve the request body exactly as signed.

  2. 02
    Verify signature + age

    Reject a bad HMAC or timestamp outside the replay window.

  3. 03
    Hash, then parse

    Create a SHA-256 digest before reading the event envelope.

  4. 04
    Claim atomically

    SQLite decides first delivery, duplicate, or ID collision.

  5. 05
    Record the outcome

    Keep evidence metadata; payload_body: not retained.

Case file · duplicate fulfilment

“We received the same payment twice.”

The provider saw two successful responses. The application team saw two deliveries. Neither fact proves that two business actions should have happened.

1

Reproduce. Send one signed payment fixture, then instruct the CLI to repeat it.

2

Compare. Both rows have evt_pay_81 and digest 8f21…d903.

3

Conclude. This was a normal retry. The receiver claimed it once and acknowledged both attempts.

TerminalReproduce the retry
$ webhooklab chaos payment.succeeded \
    --event-id evt_pay_81 --duplicate

→ attempt 1  202 processed

→ claims     1

$ webhooklab ledger --event evt_pay_81
digest        8f21…d903
payload_body  not retained
Finding

If fulfilment still ran twice, investigate the application’s idempotency boundary. The delivery evidence does not support two distinct provider events.

Quickstart

Run a receiver in a few commands

Use the installed webhooklab command to start the local ledger, then send fixtures from a second terminal.

Terminalinstall + listen

$ cd webhook-delivery-debugger
$ python -m venv .venv
$ source .venv/bin/activate
$ pip install -e ".[dev]"

Scope

A debugging receiver, not a gateway

Use it locally for retry, ordering, signature, and collision investigations. It does not queue production traffic, manage provider retries, or replace provider logs. A hosted deployment would still need authentication, tenant isolation, encrypted secrets, rate controls, retention policy, and durable backups.
